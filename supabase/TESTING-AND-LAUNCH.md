# ORVEXAL — إعداد الاختبار والإطلاق

## الحالة الحالية
- واجهة الموقع ثابتة وتعمل على GitHub Pages.
- ملف `supabase-config.js` مضبوط على مشروع Supabase الحالي باستخدام publishable key فقط.
- جداول `profiles`, `plans`, `orders`, `subscriptions` موجودة وRLS مفعّل.
- دالتا Edge Function منشورتان: `create-checkout` (JWT مطلوب) و`paytabs-callback` (تستقبل إشعار مزود الدفع ثم تتحقق من العملية عبر API).
- الأسعار في قاعدة البيانات: 15.000 JOD شهرياً و50.000 JOD سنوياً.
- الباقتان غير نشطتين حالياً، لذلك أزرار الدفع تبقى مغلقة حتى يكتمل إعداد PayTabs.

## إعداد مفاتيح PayTabs — لا تستخدم قيماً وهمية
أضف القيم الحقيقية من لوحة PayTabs إلى Supabase Edge Function Secrets فقط:
- `PAYTABS_SERVER_KEY`
- `PAYTABS_PROFILE_ID`
- `SITE_URL` (عنوان الموقع المنشور)

لا تضع Server Key أو Service Role Key أو أي سر في ملفات الواجهة أو GitHub. لا توجد مفاتيح اختبار عشوائية صالحة لدى PayTabs؛ استخدم بيانات Sandbox الصادرة من حساب التاجر نفسه.

## فحوصات ما قبل الإطلاق
1. فعّل SMTP موثوقاً في Supabase Auth، واضبط Site URL وRedirect URLs للدومين المنشور.
2. أضف أسرار PayTabs الرسمية إلى Edge Functions.
3. اختبر إنشاء الحساب وتأكيد البريد وتسجيل الدخول واستعادة كلمة المرور.
4. اختبر طلب دفع ناجح ومرفوض ومكرر في بيئة Sandbox.
5. تأكد أن callback لا يفعّل الاشتراك إلا بعد استعلام تحقق ناجح من PayTabs ومطابقة رقم الطلب والمبلغ والعملة.
6. بعد نجاح جميع الاختبارات، فعّل خطط VIP ثم انتقل إلى بيانات Live بعد موافقة التاجر.

## ملاحظة أمان
لا تستخدم بيانات تجريبية لتمثيل دفعة حقيقية، ولا تنشئ اشتراكاً مدفوعاً دون تحقق خادمي من مزود الدفع. الرجوع إلى صفحة النجاح في المتصفح ليس دليلاً على الدفع.
