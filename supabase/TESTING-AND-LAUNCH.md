# ORVEXAL — إعداد الاختبار والإطلاق

## الحالة التي تم التحقق منها
- مستودع الواجهة يحتوي على الصفحات التعليمية والحسابات والباقات وصفحة عودة الدفع.
- ملف supabase-config.js يستخدم عنوان مشروع Supabase وPublishable Key عام فقط.
- مشروع Supabase نشط، والجداول profiles, plans, orders, subscriptions موجودة وRLS مفعّل عليها.
- دالتا الدفع المعتمدتان منشورتان: create-checkout (JWT مطلوب) وpaytabs-callback (JWT غير مطلوب لأنها تستقبل إشعار PayTabs وتتحقق من العملية عبر API). توجد دالة قديمة إضافية باسم clever-handler وليست جزءاً من مسار الدفع الجديد.
- الأسعار المسجلة: 15.000 JOD شهرياً و50.000 JOD سنوياً.
- الباقتان غير نشطتين حالياً، وأزرار الاشتراك تبقى مغلقة إلى حين إكمال إعداد التاجر والاختبارات.
- فحص Supabase الأمني لم يُظهر تنبيهات وقت الفحص.

## إعداد مفاتيح PayTabs — لا تستخدم قيماً وهمية
أضف القيم الحقيقية من لوحة PayTabs إلى Supabase Edge Function Secrets فقط:
- PAYTABS_SERVER_KEY
- PAYTABS_PROFILE_ID
- SITE_URL (عنوان الموقع المنشور)

لا تضع Server Key أو Service Role Key أو أي سر في ملفات الواجهة أو GitHub. استخدم بيانات Sandbox الصادرة من حساب التاجر نفسه.

## فحوصات ما قبل الإطلاق
1. فعّل SMTP موثوقاً في Supabase Auth، واضبط Site URL وRedirect URLs للدومين المنشور.
2. أضف أسرار PayTabs الرسمية إلى Edge Functions.
3. اختبر إنشاء الحساب وتأكيد البريد وتسجيل الدخول واستعادة كلمة المرور.
4. اختبر طلب دفع ناجح ومرفوض ومكرر في بيئة Sandbox.
5. تأكد أن callback لا يفعّل الاشتراك إلا بعد استعلام تحقق ناجح من PayTabs ومطابقة رقم الطلب والمبلغ والعملة.
6. اختبر انتهاء الاشتراك والإلغاء والاسترداد وسياسة التجديد.
7. بعد نجاح جميع الاختبارات وموافقة التاجر، فعّل خطط VIP ثم انتقل إلى بيانات Live.

## ملاحظة أمان
لا تستخدم بيانات تجريبية لتمثيل دفعة حقيقية، ولا تنشئ اشتراكاً مدفوعاً دون تحقق خادمي من مزود الدفع. الرجوع إلى صفحة النجاح في المتصفح ليس دليلاً على الدفع.
